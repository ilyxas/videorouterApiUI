## Текущая поставка

Workflow состоит из Steps с DAG карточек и Continue/Pause между Steps. Image/Video/Audio наследуют BaseCard по типу output. Типизированные связи работают внутри Step и из предыдущих Steps. Режимы переключаются в карточке, дополнительные параметры доступны через API Explorer с возвратом в workflow. Добавлен шаблон точного двухэтапного acceptance.

Steps можно удалять и переставлять с сохранением порядка зависимостей, переключать между Cards и Flow. Flow показывает квадраты с миниатюрами и стрелками слева направо, карточки имеют чередующийся фон. Запуск и результаты остаются в редакторе. Отключённые Steps используют последний или закреплённый успешный output без API-вызова и повторного расхода; без output пропускаются. Зависимые карточки с недостаточными входами пропускаются с причиной. Во время run доступны будущие enabled и Continue/Pause; на паузе — редактирование будущих Steps.

References передаются URL/data URI без обязательного внешнего upload; предусмотрен fallback для больших файлов и URL-only API. Сохранены предварительные оценки, точная оценка перед генерацией, история, drafts, прежние workflow и данные. V1 сохраняется отдельно при миграции. Pause/resume не повторяет завершённые Steps.

## Запуск и данные

`server.mjs` и обязательный `tailscale.mjs` работают совместно. После обновления отдельной командой подтверждены HTTP localhost и Tailscale. Использованы разовые launchd jobs; постоянный автозапуск не добавлялся. `studio.sh` всё ещё использует nohup; его историческое ограничение описано в 09/10. Не перезапускать сервис ради чтения handoff или при активных заданиях.

Ключи из вложений подключены только в память сервера. Git инициализирован, исходное состояние и реализация закоммичены; данные, ключи и backups игнорируются. В Handoff нет ключей, пользовательских медиа или SQLite. Снимки 01–08 и source-hashes относятся к исходному аудиту; новые доказательства имеют отдельные номера.
