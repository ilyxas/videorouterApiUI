# Итерация 2: согласованная оценка и изображение → видео

> Исторический отчёт. Блокировка предварительной оценки до готовности входа и узкая форма Image **заменены исправлением 08**. Сейчас неполный шаг можно оценить отдельно. Актуальное состояние — [09](09-current-state-and-next-thread.md); перед продолжением этапа 4 нужен replan.

17 ноября 2026. Выполнен основной сценарий этапов 2–3 плана; полная матрица всех моделей/режимов остаётся отдельным этапом.

Реализовано:
- `public/workflow-core.mjs`: общая нормализация запроса и подготовка оценки. В оценку передаются все параметры, включая входы, provider и failover. Длительность видео 5 секунд остаётся 5 в обоих запросах, даже если запись длится 8 секунд; автоматической подмены только при оценке больше нет.
- Пока ссылка на будущий output или upload не разрешена, оценка явно отложена. Компилятор помечает генерации изображений/видео для обязательного расчёта по готовому запросу перед отправкой. Ошибка оценки останавливает цепочку. Подтверждение показывает справочную политику цены, без обещания лимита списаний. Результат оценки хранится в истории; сохранённая предварительная оценка помечается устаревшей после изменений.
- Удобный шаг Text to Image с gpt-image-1, prompt и n. Другие параметры доступны в API Explorer. Кнопки «Изображение N → видео» и выбор из входного слота создают явную связь по стабильному ID, порту и номеру output. Результаты не размножают видеозапросы автоматически.
- Проверки типа входа, порядка, удалённого источника, доступности номера, подтверждённой поддержки image-to-video. Смена модели не удаляет связанное изображение молча. Старые позиционные ссылки поддерживаются.
- `artifacts.mjs`: адаптер ответа POST /v1/images для URL и base64 PNG/JPEG/WebP. Base64 сохраняется локальным asset, затем подставляется в start_image_url как data URI; URL используется напрямую. Проверяются доступность локального файла, известное истечение и тип данных. В истории перечислены все артефакты, локальные изображения имеют preview, удалённые результаты — ссылку открытия.
- Сворачивание карточек с видимой связью. При ошибке оставшиеся последовательные шаги получают статус blocked, повторная генерация автоматически не запускается.

Контракты проверены по официальным страницам:
- https://videorouter.sh/docs/api-reference — pricing/estimate, uploads.
- https://videorouter.sh/docs/api-reference-images — n, URL/base64 response.
- https://videorouter.sh/docs/api-reference-video — start_image_url принимает HTTPS/data URI; async job/polling.
- https://videorouter.sh/docs/image-generation и https://videorouter.sh/docs/video-generation — примеры.

Проверено 11 тестов: сохранность предыдущей итерации, регрессия 8/5 секунд и полное равенство оценённого/отправленного JSON, стабильность связи, URL/base64, неправильные типы, отсутствие файла/выбранного output, просроченный результат, ошибка источника/оценки без отправки видео, ожидание async video, запись истории после перезапуска. Интеграционные тесты работают во временной БД, внешний fetch полностью подменён.

В браузере: создание изображения, изменение n с немедленным обновлением кнопок, выбор второго результата, объяснение отложенной оценки, reload связи, весь запуск с фикстурами, открытие из истории без генерации, компактная цепочка на 390 px без горизонтального переполнения. Платных API-проверок не было: расходы $0, бюджет $10 не использован.

Границы: нет ручной паузы выбора после генерации (используется заранее выбранный номер), полного каталога режимов/провайдерных ограничений, повторного использования output из другого запуска и биллингового лимита. Реальный end-to-end у провайдера не выполнялся. При неуказанном TTL доступность удалённой ссылки заранее не гарантируется. Задания не возобновляются автоматически после остановки сервера. Прежнее предложение продолжать этапы 4–5 заменено текущим поручением: сначала replan архитектуры workflow, затем продолжение этапа 4.
