# VideoRouter API Studio

Локальная веб-консоль VideoRouter. Требуется Node.js 26. Установка пакетов не нужна.

```sh
cd /Users/ilya/Development/Challange/videorouterApiUI
./studio.sh          # запуск в фоне
./studio.sh restart  # перезапуск
./studio.sh status   # состояние
./studio.sh logs     # лог, Ctrl+C для выхода
./studio.sh stop     # остановка
```

Открыть http://127.0.0.1:8791. Без аргументов `studio.sh` запускает в фоне оба процесса: `server.mjs` и обязательный `tailscale.mjs`. Команды `restart`, `stop` и `status` управляют ими совместно. Tailscale на Mac должен быть подключён; успешный запуск подтверждается только после ответа локального сервера и прокси. Если новый прокси не запускается, новый сервер также останавливается. При уже работающем сервере `start` восстанавливает отсутствующий прокси. Порт можно выбрать через `PORT=8792 ./studio.sh start`; перезапуск сохраняет выбранный порт. Общий лог — `data/studio.log`. Адрес для телефона: http://100.80.72.44:8791. Прокси сохраняет ограничения существующего `tailscale.mjs`: доступ только с Mac `100.80.72.44` и телефона `100.121.194.63`. При изменении адресов используйте `TAILSCALE_MAC_IP` и `TAILSCALE_PHONE_IP`; `restart` сохраняет адреса работающего прокси, если переопределение не задано. Скрипт не создаёт второй процесс, не останавливает чужие процессы и отменяет остановку/перезапуск при активных заданиях. Сервер, запущенный вручную, сначала остановите в его терминале. После перезапуска ключи из интерфейса нужно ввести заново; ключи из окружения передаются новому процессу. Для работы в переднем плане по-прежнему доступен `node server.mjs` с остановкой через Ctrl+C. Сам `server.mjs` слушает только loopback, а `tailscale.mjs` — указанный Tailscale IPv4.

## Подключение

В разделе «Подключение» ввести API key или задать VIDEOROUTER_API_KEY при старте. Management key нужен для /keys и /usage. Можно задать его через VIDEOROUTER_MANAGEMENT_KEY. После ввода ключа запросить баланс и обновить список моделей. Публичный каталог хранится локально, реальный доступ определяют права ключа, провайдер и баланс.

## Workflow

Открыть [шаблон LTX](http://127.0.0.1:8791/#ltx). В шаге «Создать видео» выбрать звуковую дорожку с компьютера, по HTTPS-ссылке или озвучить введённый текст. Для результата предыдущего шага выбрать «Из шага». Для стартового изображения также можно выбрать файл или ссылку. Затем описать сцену и указать длительность под запись. Доступные сочетания входов зависят от модели и хоста.

Через «Добавить шаг» доступны создание изображения, озвучка, видео, оживление портрета, расшифровка и передача файла. Дополнительные операции доступны в API Explorer. При запуске студия сама подставляет результаты и передаёт выбранные локальные файлы в VideoRouter, когда модели нужен URL.

Черновик workflow автоматически сохраняется в этом браузере и восстанавливается после перезагрузки, включая незавершённое редактирование параметров шага. Это один черновик на адрес сервера; для постоянной именованной копии используйте «Сохранить». Очистка данных браузера удаляет черновик. Сохранение схемы и выбор файла работают локально. Кнопка выполнения показывает фактическую конфигурацию отправки. Платные действия и загрузки выполнять только по конкретному разрешению Ильи. Не повторять запрос создания при неизвестном результате. Для восстановления использовать сохранённый ID и соответствующий GET в API Explorer.

## Изображение → видео и стоимость

Добавьте «Создать изображение», введите описание и количество результатов. Нажмите «Изображение N → видео» для нужного номера либо выберите этот результат во входе «Стартовое изображение → Из шага». Связь создаётся до запуска и сохраняется по ID шага. Видео использует только явно выбранный результат. Карточки можно сворачивать.

Сначала выполняется генерация изображения, затем выбранный URL или base64 автоматически передаётся как стартовый кадр совместимой видеомодели. Base64 сохраняется локально и передаётся как data URI, без дополнительного upload. При отсутствующем/просроченном результате цепочка останавливается без автоматического повторного создания. Известный срок ссылки проверяется локально; недоступность удалённого URL без известного срока может обнаружиться только у провайдера.

Оценка и отправка используют общую нормализацию и все параметры запроса. Для видео используется явно заданная длительность: ввод длины аудио больше не заменяет её только в оценке. Изменение параметров помечает сохранённую оценку устаревшей. Предварительная оценка доступна по заполненным параметрам одного шага, даже без готового входа и prompt. Пропущенные входы и допущения показываются рядом с ценой; перед каждым изображением/видео в workflow цена уточняется по фактическому запросу. Подтверждение запуска сообщает, что эта оценка справочная, не ограничивает расходы, а ошибка расчёта остановит цепочку. Неизвестная цена (например, токены изображения) остаётся неизвестной до результата. В истории сохраняются запрос оценки, её ответ и фактические параметры генерации.

Проверки без внешнего API: `node --test tests/*.test.mjs`. Транспорт из `tests/offline-transport.mjs` используется только тестами; обычный запуск `node server.mjs` обращается к реальному API.

## Контракты и действия Image

Через «Добавить шаг» доступны три действия Image. Кнопки «Изображение N → редактировать / увеличить / видео» создают следующий шаг и связывают выбранный результат. Редактирование использует Gemini 2.5 Flash Image, увеличение — Recraft Crisp Upscale с одним исходным изображением. JSON и перенос URL не нужны. «＋ После» вставляет шаг в нужное место; верхние кнопки переходят к карточкам.

Списки Image и Video используют каталог моделей и явно объявленные возможности входов; они не ограничены GPT Image и LTX. Общий реестр проверяет параметры endpoint и специальные ограничения известных профилей. Для видео с выбранной аудиодорожкой показываются LTX-модели: API поддерживает одиночный аудиовход только у них. Пустой выбор аудиофайла не ограничивает список. При смене видеомодели параметры и входы не удаляются. Пять пока неподключённых видеорежимов показываются с причиной недоступности. Произвольные запросы доступны отдельно в API Explorer.

Карточка изображения содержит модель, формат и качество. Для GPT Image 1 по умолчанию используются явные 1024×1024 и medium, одинаково в оценке и генерации. В предварительной оценке изменения допущений API показываются без блокировки расчёта. Если оценка непосредственно перед генерацией явно изменила запрошенную длительность или размер, генерация останавливается. Это не гарантирует фактические размеры результата, когда API не сообщает их. Полный статус этапов и ограничения: [Handoff/08-quote-model-format-fix.md](Handoff/08-quote-model-format-fix.md).

## Ответы и хранение

Ключи подключения остаются в памяти. SQLite, файлы пользователя и полученные бинарные результаты находятся в data/. JSON-ответы, сумма известных списаний, ошибки и ID удалённых заданий сохраняются по шагам. Новые запуски также хранят исходный workflow, план технических операций и фактические параметры перед отправкой каждого запроса. Из истории конфигурацию можно открыть как новый черновик без выполнения запросов. Старые запуски без конфигурации помечены отдельно. При перезапуске незаконченные запуски помечаются прерванными. API-ключи, созданные запросом POST /keys, и данные подключения из ответов на создание live-сессий и токенов доступны до остановки процесса.

Realtime предоставляет консоль JSON-событий WebSocket. Для мультимедиа в live-видеосессиях требуется клиент соответствующего провайдера (LiveKit, Daily и другие). Локальный сервер не принимает публичные webhook. Для обычных асинхронных workflow используется polling. Публичные URL результатов могут истекать.
