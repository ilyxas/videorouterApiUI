# VideoRouter API Studio

Локальная веб-консоль VideoRouter. Требуется Node.js 26. Установка пакетов не нужна.

Документация: [карта проекта](Handoff/README.md) · [архитектура](Handoff/10-workflow-v2.md) · [контракт агента](contracts/workflow/README.md) · [тесты и результаты](tests/TESTING.md).

```sh
cd /Users/ilya/Development/Challange/videorouterApiUI
./studio.sh          # запуск в фоне
./studio.sh restart  # перезапуск
./studio.sh status   # состояние
./studio.sh logs     # лог, Ctrl+C для выхода
./studio.sh stop     # остановка
```

Открыть http://127.0.0.1:8791. Без аргументов `studio.sh` запускает в фоне оба процесса: `server.mjs` и обязательный `tailscale.mjs`. Команды `restart`, `stop` и `status` управляют ими совместно. Tailscale на Mac должен быть подключён; успешный запуск подтверждается только после ответа локального сервера и прокси. Если новый прокси не запускается, новый сервер также останавливается. При уже работающем сервере `start` восстанавливает отсутствующий прокси. Порт можно выбрать через `PORT=8792 ./studio.sh start`; перезапуск сохраняет выбранный порт. Общий лог — `data/studio.log`. Адрес для телефона: http://100.80.72.44:8791. Прокси сохраняет ограничения существующего `tailscale.mjs`: доступ только с Mac `100.80.72.44` и телефона `100.121.194.63`. При изменении адресов используйте `TAILSCALE_MAC_IP` и `TAILSCALE_PHONE_IP`; `restart` сохраняет адреса работающего прокси, если переопределение не задано. Скрипт не создаёт второй процесс, не останавливает чужие процессы и отменяет остановку/перезапуск при активных заданиях. Сервер, запущенный вручную, сначала остановите в его терминале. После перезапуска ключи из интерфейса нужно ввести заново; ключи из окружения передаются новому процессу. Для работы в переднем плане по-прежнему доступен `node server.mjs` с остановкой через Ctrl+C. Сам `server.mjs` слушает только loopback, а `tailscale.mjs` — указанный Tailscale IPv4.

## Подключение

В разделе «Подключение» ввести API key или задать VIDEOROUTER_API_KEY при старте. Management key нужен для /keys и /usage. Можно задать его через VIDEOROUTER_MANAGEMENT_KEY. После ввода ключа запросить баланс и обновить список моделей. Публичный каталог хранится локально, реальный доступ определяют права ключа, провайдер и баланс.

### Webhook + polling

В разделе «Подключение» добавлен блок **Webhook + polling**. Обычный polling остаётся включённым с прежним интервалом: 4 секунды для видео и Jobs, 15 секунд для legacy Batch. Без настройки webhook приложение работает как раньше.

1. Ввести публичный URL `https://ilyas-macbook-air.tail3c03cd.ts.net/webhooks/videorouter` и **webhook secret** из VideoRouter → Org admin → Webhooks. API key и management key не заменяют этот секрет. Нажать «Подключить webhook».
2. Приёмник запускается на `127.0.0.1:8792`. Тестовый Node-сервер из предыдущей инструкции должен быть остановлен. При другом порте Studio по умолчанию используется `PORT + 1`; переопределение — `WEBHOOK_PORT`.
3. Направить Funnel на приёмник: `tailscale funnel --bg 8792`. Проверить публичный URL с путём `/health` с устройства вне Tailscale; ожидается `Webhook receiver OK`. Основной интерфейс остаётся на 8791.
4. Новые задания `/v1/videos`, `/v1/lipsync`, `/v1/face-swap` и `/v1/jobs` получают callback с уникальным ID попытки. Явные `webhook_url: null` и сторонний callback в API-параметрах сохраняются. Images, обычные Audio и остальные операции работают прежним способом.

URL и настройка включения сохраняются в SQLite; секрет остаётся только в памяти процесса. После перезапуска его нужно подключить снова. Для запуска через окружение: `VIDEOROUTER_WEBHOOK_URL`, `VIDEOROUTER_WEBHOOK_SECRET`, необязательный `VIDEOROUTER_WEBHOOK_ENABLED=0` для отключения. Секрет не возвращается через local API и не попадает в историю запросов.

Приёмник проверяет HMAC по исходным байтам, сохраняет доставку до подтверждения и будит существующий runner. Первый терминальный ответ polling/webhook определяет output, остальные не выполняют Step повторно. Поздняя окончательная цена дополняет расход, включая архивированную попытку после выбора другого output. Если в терминальном ответе нет цены, GET существующего задания выполняется отдельно раз в 4 секунды до часа; при следующем старте сервера ожидание незавершённой сверки возобновляется. Новых генераций эта сверка не создаёт.

Pause, ручной запуск Step, выключенные Steps и pinned outputs сохраняют свою логику. После остановки сервера прерванный v2 run восстанавливается прежней кнопкой Recover; сохранённое уведомление может дать результат без нового запроса генерации. Неизвестный POST автоматически не повторяется. Funnel не хранит сообщения за выключенный Mac.

«Отключить webhook» закрывает приёмник и очищает секрет в памяти; polling продолжает работать. Отключение публичного маршрута Tailscale: `tailscale funnel --https=443 off`.

## Workflow

Workflow v2 состоит из последовательности **Steps**, внутри каждого — направленный ациклический граф карточек. `ImageCard`, `VideoCard` и `AudioCard` наследуют `BaseCard`; тип определяется выходом операции. Связь задаёт исходную карточку, порт и номер результата, а также вход и слот получателя. Карточки выполняются по зависимостям. Между Steps по умолчанию включено «Продолжить»; выключение ставит запуск на паузу после завершения Step. На паузе можно изменить любой Step, отдельно перегенерировать его или выбрать прежний output и затем продолжить.

Кнопка **«Шаблон: Image → Edit → References»** создаёт два Steps: первый содержит генерацию и редактирование изображения, второй — видео по референсам. Для второго референса выберите локальный файл. В Image/Video/Audio есть переключатель режима; параметры выбранной карточки можно открыть в API Explorer и вернуть в workflow. Старые workflow конвертируются при открытии; при сохранении v1 создаётся новая v2-копия, оригинал остаётся.

Открыть [шаблон LTX](http://127.0.0.1:8791/#ltx). В шаге «Создать видео» выбрать звуковую дорожку с компьютера, по HTTPS-ссылке или озвучить введённый текст. Для результата предыдущего шага выбрать «Из шага». Для стартового изображения также можно выбрать файл или ссылку. Затем описать сцену и указать длительность под запись. Доступные сочетания входов зависят от модели и хоста.

Добавление карточек охватывает Image, Video, Audio, текстовые и произвольные API-операции. Для URL и небольших локальных файлов референсы передаются прямо в запросе; внешний upload используется для URL-only входов или когда суммарный inline body превысил бы 8 MiB. Выбор файла в форме сохраняет его только на локальном сервере.

Черновик workflow автоматически сохраняется в этом браузере и восстанавливается после перезагрузки, включая незавершённое редактирование параметров шага. Это один черновик на адрес сервера; для постоянной именованной копии используйте «Сохранить». Очистка данных браузера удаляет черновик. Сохранение схемы и выбор файла работают локально. Кнопка выполнения показывает фактическую конфигурацию отправки. Платные действия и загрузки выполнять только по конкретному разрешению Ильи. Не повторять запрос создания при неизвестном результате. Для восстановления использовать сохранённый ID и соответствующий GET в API Explorer.

У каждого Step есть удаление, перемещение ↑/↓, переключатель «Включён» и вид Flow/Карточки. Flow показывает компактные карточки со стрелками слева направо; нажатие раскрывает редактор выбранной карточки. Перестановка не может перенести источник после потребителя. Удаление Step убирает его карточки и связи, сохраняя историю и файлы. Фон карточек чередуется внутри каждого Step.

Отключённый Step не вызывает API: использует последний успешный output каждой карточки либо выбранный в списке прежний результат. Если output отсутствует, вход пропускается; зависимая карточка выполняется при достаточных оставшихся входах, иначе тоже пропускается с причиной. Стоимость reused output не добавляется к новому запуску. Изменённые параметры не подменяют сохранённый результат: для нового результата включите Step.

Запуск, статусы и медиа остаются в редакторе workflow. Во время работы можно отключать/включать будущие Steps и менять Continue/Pause; начавшийся Step уже нельзя выключить. «Пауза после текущего Step» останавливает автоматическое продвижение. На паузе доступны редактирование любого Step, выбор outputs и кнопка «Запустить Step» у каждого Step. Эта кнопка выполняет только выбранный Step (даже выключенный), используя сохранённые inputs остальных. Повторный результат становится последним успешным; старые результаты остаются в списке. «Продолжить workflow» передаёт выбранные outputs пройденных Steps дальше, без неявной повторной генерации. Чтобы новые параметры дали новый output, сначала нажмите «Запустить Step». Расход отдельного запуска виден отдельно; уже понесённые расходы исходного run сохраняются. Одновременно допускается один активный run одного workflow.

### Characters, locations, and Workflow Flow

Open **Characters** for reusable character profiles, or **Locations** for reusable places. A location can represent a house with exterior and room assets, a stadium with several viewpoints, or another place of your choice. Store its description, visual appearance, spatial layout, scenario notes, and described local assets. Character audio assets are voice samples; location audio assets are ambience. Duplicate either kind to create an independent variant.

In a workflow, **Characters & locations** provides **Add from library**, **Create character**, and **Create location**. Each card is an independent snapshot outside the Steps and can be added only once by ID. **Edit snapshot** affects that workflow only; **Save as new library character/location** creates a reusable entry. Local files remain in `data/files` until an executing API request needs them.

For typed media inputs, choose **Card asset**, then a character or location asset. Combine these with files, URLs, and Step outputs in the required order. Removing a referenced card or asset marks affected inputs for reattachment without deleting files or other snapshots. Keep identity and environment sources distinct when composing a scene.

**Workflow Flow** shows Steps and character/location sources. Purple lines identify character references; teal identifies location references. Tap an API card to open its editor and highlight connections, or a source card to edit its snapshot. On phones, the graph uses a compact vertical layout. Step controls remain below it.

**Export agent context** on either library page exports both kinds with descriptions and stable asset IDs. See the [workflow contract](contracts/workflow/README.md) for JSON construction and `--asset-context FILE` validation.

### Импорт, экспорт и удаление

Workflow JSON export includes the v2 graph, parameters, Step flags/views, optional CharacterCard and LocationCard snapshots, and global view preference. It excludes media bytes, run history, results, and connection keys. Ordinary local inputs require reattachment. DataCard file references reconnect automatically when the same registered file exists in the target Studio; otherwise the snapshot keeps its descriptions and marks the asset for reattachment. Imported copies do not inherit pinned outputs or another workflow's results.

Импорт показывает состав и предупреждения, затем сохраняет отдельный workflow с новым ID. Исходные workflows сохраняются; генерация не запускается. Перед импортом сохраните нужный текущий черновик. Поддерживаются канонический JSON v2 и прежняя схема workflow; максимальный размер файла — 3 MiB. Неверные операции, циклы и некорректные связи отклоняются до сохранения. Схему и параметры можно редактировать вне Studio и импортировать обратно.

В **Workflow → «Открыть»** у сохранённых workflows есть кнопка **«Удалить»**. Удаляется только схема, история и локальные файлы остаются. В **«Истории»** можно удалить отдельную запись или **«Очистить завершённые»** — записи completed/failed/interrupted. Массовая очистка сохраняет паузы и активные запросы. Отдельную паузу можно удалить с предупреждением, после чего продолжить её будет нельзя. Перед удалением показывается подтверждение, включая зависимости закреплённых outputs. Работающие и восстанавливаемые запросы защищены от удаления. Удаление истории не отменяет удалённые задания и не возвращает списания; локальные файлы остаются, поскольку могут использоваться другими workflows.

### Контракт построения workflow для агента

[Рабочий контракт](contracts/workflow/README.md) задаёт правила возврата импортируемого JSON v2: [JSON Schema](contracts/workflow/workflow.schema.json), [реестр операций](contracts/workflow/operations.json), типы входов/выходов, порядок референсов, связи внутри и между смешанными Steps. Раскадровка и промпты передаются как решения задачи/скиллов; контракт их не заменяет. Агент возвращает JSON без генераций. Skills и встроенный ИИ-помощник этой поставкой не добавляются.

Проверка готового файла без сети и записи в базу: `node contracts/workflow/validate.mjs /absolute/path/workflow.json`. Флаг `--ready` дополнительно требует прохождения локальной проверки обязательных входов перед исполнением. Успешный импорт и готовность к исполнению показаны раздельно: локальный файл может требовать повторного выбора. Модельные возможности и фактическая доступность URL внешним запросом не проверяются.

Описание проверок контракта, точные задания агентам и результаты находятся в [документе тестов](tests/TESTING.md).

## Изображение → видео и стоимость

Добавьте «Создать изображение», введите описание и количество результатов. Нажмите «Изображение N → видео» для нужного номера либо выберите этот результат во входе «Стартовое изображение → Из шага». Связь создаётся до запуска и сохраняется по ID шага. Видео использует только явно выбранный результат. Карточки можно сворачивать.

Сначала выполняется генерация изображения, затем выбранный URL или base64 автоматически передаётся как стартовый кадр совместимой видеомодели. Base64 сохраняется локально и передаётся как data URI, без дополнительного upload. В Workflow v2 отсутствующий/просроченный output пропускается; карточки с недостаточными входами тоже пропускаются, независимые ветки продолжаются. Автоматического повторного создания нет. Известный срок ссылки проверяется локально; недоступность удалённого URL без известного срока может обнаружиться только у провайдера.

Оценка и отправка используют общую нормализацию и все параметры запроса. Для видео используется явно заданная длительность: ввод длины аудио больше не заменяет её только в оценке. Изменение параметров помечает сохранённую оценку устаревшей. Предварительная оценка доступна по заполненным параметрам одного шага, даже без готового входа и prompt. Пропущенные входы и допущения показываются рядом с ценой; перед каждым изображением/видео в workflow цена уточняется по фактическому запросу. Подтверждение запуска сообщает, что эта оценка справочная, не ограничивает расходы, а ошибка расчёта остановит цепочку. Неизвестная цена (например, токены изображения) остаётся неизвестной до результата. В истории сохраняются запрос оценки, её ответ и фактические параметры генерации.

Команды offline-проверок и условия отдельных платных прогонов описаны в [документе тестов](tests/TESTING.md). Обычный запуск Studio использует реальный API.

## Контракты и действия Image

Image включает генерацию, редактирование, увеличение, virtual try-on и image output через chat. Video включает text/image/audio/reference-to-video, edit, extend, motion control, upscale, keyframes, draft finalization, lip-sync, face swap и avatar. Audio включает speech, music, sound effects и audio output через chat. Transcription остаётся текстовым выходом. Возможности и обязательные входы определяются реестром операций; доступность конкретного провайдера зависит от API.

Списки Image и Video используют каталог моделей и явно объявленные возможности входов; они не ограничены GPT Image и LTX. Общий реестр проверяет параметры endpoint и ограничения известных профилей. Одиночный аудиовход используется с поддерживающими его LTX-моделями. При смене модели параметры и входы не удаляются. Произвольные запросы доступны отдельно в API Explorer. Наличие режима в редакторе не означает платную проверку всех моделей и провайдеров.

Карточка изображения содержит модель, формат и качество. Для GPT Image 1 по умолчанию используются явные 1024×1024 и medium, одинаково в оценке и генерации. В предварительной оценке изменения допущений API показываются без блокировки расчёта. Если оценка непосредственно перед генерацией явно изменила запрошенную длительность или размер, генерация останавливается. Это не гарантирует фактические размеры результата, когда API не сообщает их. Полный статус этапов и ограничения: [Handoff/08-quote-model-format-fix.md](Handoff/08-quote-model-format-fix.md).

## Ответы и хранение

Ключи подключения остаются в памяти. SQLite, файлы пользователя и полученные бинарные результаты находятся в data/. JSON-ответы, сумма известных списаний, ошибки и ID удалённых заданий сохраняются по шагам. Новые запуски также хранят исходный workflow, план технических операций и фактические параметры перед отправкой каждого запроса. Из истории конфигурацию можно открыть как новый черновик без выполнения запросов. Старые запуски без конфигурации помечены отдельно. При перезапуске незаконченные запуски помечаются прерванными. API-ключи, созданные запросом POST /keys, и данные подключения из ответов на создание live-сессий и токенов доступны до остановки процесса.

Realtime предоставляет консоль JSON-событий WebSocket. Для мультимедиа в live-видеосессиях требуется клиент соответствующего провайдера (LiveKit, Daily и другие). Webhook принимается отдельным opt-in приёмником; polling сохраняется. Публичные URL результатов могут истекать.

Архитектура, миграция и ограничения Workflow v2: [Handoff/10-workflow-v2.md](Handoff/10-workflow-v2.md).
