# Правила работы с проектом

## Обязательное обновление Handoff

**Что-то поменял в проекте — зафиксировал актуальное состояние в Handoff.**

- Перед работой прочитай `Handoff/README.md` и указанную в нём актуальную сводку.
- Каждое завершённое исправление или изменение кода, конфигурации, тестов либо документации должно сопровождаться обновлением Handoff до итогового ответа пользователю.
- Обновляй существующие документы по месту. Не создавай новый файл для каждого исправления, запуска, даты или сессии; не размножай копии отчётов и сводок. Новый документ нужен только для отдельной темы, которая не помещается по смыслу в существующие документы, либо по прямому запросу пользователя.
- Handoff должен описывать текущее состояние проекта: что изменено, что реально проверено и с каким результатом, какие ограничения и незавершённые задачи остаются. Если проверка не выполнялась, прямо укажи это. Состояние запуска и ссылки на коммиты обновляй, когда они изменились и были проверены.
- `Handoff/README.md` всегда остаётся точкой входа и ведёт на актуальные документы. Исправляй устаревшие утверждения, а не добавляй рядом противоречащие им записи.
- Отличай завершённую поставку от работы в процессе. Не выдавай незавершённые изменения или старые результаты проверок за подтверждённое текущее состояние.
- Для одного исправления достаточно одного согласованного обновления существующих документов; отдельный отчёт об обновлении Handoff не нужен.

Изменение считается завершённым только вместе с актуальным Handoff.
